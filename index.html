Project Objective

Educational Scope and Purpose

“To provide an interactive and reproducible software simulation for understanding 8086 port-mapped I/O operations using virtual devices, IN/OUT instructions, port mapping and execution tracing.”

In physical 8086 microcomputer systems, input/output interfacing requires specialized hardware logic, address decoders (74LS138), bus transceivers (74LS245), and bus control signal decoding (M/~IO = 0, ~RD = 0, ~WR = 0). This educational simulation allows students to interact with, trace, and debug 8086 isolated I/O operations without the safety and hardware constraint barriers of physical ICs.

⚠️

Real-World Problem

Why Microprocessor I/O is Difficult to Learn

Students frequently learn 8086 I/O interfacing purely theoretically. Physical breadboard interfacing with DIP switches, 8255 PPIs, and 74LS series ICs presents major hurdles:

  • Inability to pause or observe sub-microsecond T-state bus transitions
  • Risk of chip burnout from incorrect wiring or address bus conflicts
  • Lack of immediate visual feedback during accumulator data latching
  • Difficulty visualizing how the 8086 distinguishes memory addresses from 64KB I/O port addresses using control pin M/~IO

8086 Port Mapping Configuration

64KB Isolated I/O Space (0000H–FFFFH) & Address Decoding

ℹ️
Port-Mapped (Isolated) I/O vs. Memory-Mapped I/O in Intel 8086: In Port-Mapped I/O, the 8086 microprocessor uses a separate 64KB I/O address space (0000H – FFFFH) accessed exclusively via dedicated IN and OUT instructions. During I/O cycles, the control line M/~IO = 0, ensuring that memory chip-select logic remains disabled while peripheral decoders (e.g. 74LS138) activate the appropriate I/O device.

Hardware Address Decoding Logic (74LS138 3-to-8 Decoder)

In standard 8086 peripheral interfacing, address lines A2, A1, A0 are wired to the select inputs C, B, A of a 74LS138 decoder, while higher address lines A7-A3 and control line M/~IO enable the decoder:

ENABLE = (~G2A = M/~IO) AND (~G2B = A7 NOR A6 NOR A5 NOR A4 NOR A3) AND (G1 = VCC) Output: ~Y0 to ~Y7 generate individual Chip Select signals (~CS0 to ~CS7)

PROGRAM 3

Read Keypad → 7-Segment Display

IN AL, 04H   ; Read encoded scancode from Keypad at Port 04H
OUT 02H, AL  ; Output scancode to 7-Segment display Port 02H

PROGRAM 4

Read Sensor → Motor PWM Controller

IN AL, 03H   ; Sample environmental sensor at Port 03H
OUT 06H, AL  ; Drive DC Motor speed proportional to sensor
Hardware Explanation: Demonstrates closed-loop process control. As the transducer value rises, the 8086 drives a higher PWM duty cycle to the motor drive at Port 06H.
PROGRAM 5

Read Status Register → LED Indicator

IN AL, 07H   ; Sample Peripheral Handshake Flags from Port 07H
OUT 01H, AL  ; Display peripheral flags on LED indicator bar

A. Project Objective

The objective of this project is to develop an interactive, reproducible software simulation of Intel 8086 Port-Mapped (Isolated) I/O interfacing to fulfill the academic requirements of EC2201 – Microprocessor and I/O Interfacing (Unit V) for student HARIHARAN MUTHU M (Section A). The system allows students to visually explore port mapping, IN and OUT instructions, intermediate bus cycles, virtual peripherals, and fault conditions.

B. Real-World Problem

In undergraduate engineering laboratories, physical microprocessor kits (such as 8086 trainer boards with 8255 PPIs) have significant pedagogical barriers:

  • Bus signals like M/~IO, ~RD, and ~WR oscillate at megahertz frequencies, making them impossible to trace without expensive mixed-signal logic analyzers.
  • Wiring errors on breadboards easily result in short circuits, damaged ICs, or address bus floating.
  • Students struggle to grasp how the CPU executes isolated I/O versus memory-mapped I/O.

C. Proposed Solution

A full-stack interactive educational simulator that models the physical hardware behavior of the 8086 microprocessor's I/O bus interface. It executes 8086 assembly instructions, simulates 8 distinct synthetic I/O peripherals, visualizes intermediate bus cycles, updates CPU accumulator registers (AL/AH/AX), and provides detailed execution audit logs.

D. Scope of Implementation

The simulator covers:

  • Isolated (Port-Mapped) I/O addressing (8-bit direct ports 00H–FFH and 16-bit registers).
  • Instructions: IN AL, port, IN AX, port, OUT port, AL, OUT port, AX, MOV, NOP, HLT.
  • 8 Virtual I/O peripherals: DIP Switch, LED Bar, 7-Segment Display, ADC Sensor, Keypad, Piezo Buzzer, Motor Drive, and Status Register.
  • 16 automated reproducible test scenarios (10 normal + 6 edge/fault cases).

E. Documented Assumptions

  1. The project is an educational software simulation; no physical 8086 processor is connected.
  2. Virtual ports represent simulated I/O hardware peripherals.
  3. Port values are represented using standard hexadecimal notation (e.g. 03H, 5AH).
  4. Data byte values strictly range from 00H to FFH (0 to 255 decimal).
  5. The simulator focuses specifically on the Unit V Port-Mapped I/O concept.
  6. Only supported instructions (IN, OUT, MOV, NOP, HLT) are executed by the core.
  7. Reproducible synthetic data is utilized for automated verification.
  8. Peripheral physical behaviors (e.g. motor RPM, sensor temp) are modeled deterministically.
  9. The simulation does not emulate interrupt vectors or DMA controllers.
  10. The tool is safe, non-destructive, and resilient to arbitrary student input.

F. Input & Data Formats

The simulator accepts standard Intel assembly syntax:

  • Port Addresses: Hexadecimal format with 'H' suffix (e.g. 03H, 00H) or standard C notation (0x03).
  • Immediate Constants: 8-bit hex (e.g. 5AH, 0AAH) or decimal integers.
  • Assembly Programs: One instruction per line. Comments prefixed by semicolon (; comment) are ignored.

H. 8086 IN/OUT Bus Concepts

In Intel 8086 architecture:

  • IN Instruction: IN AL, port transfers an 8-bit byte from the peripheral addressed by port into accumulator register AL. The CPU asserts M/~IO = 0, ~RD = 0, and DT/~R = 0 (Receive).
  • OUT Instruction: OUT port, AL transfers an 8-bit byte from AL to the peripheral at port. The CPU asserts M/~IO = 0, ~WR = 0, and DT/~R = 1 (Transmit).

I. System Architecture

The simulator architecture consists of five decoupled layers:

  1. Presentation Layer: Responsive web GUI with SVG 7-segment display, glowing LEDs, audio synthesizer, and charts.
  2. Parser Layer: Validates syntax, decodes mnemonics, and generates friendly educational error diagnostics.
  3. Core 8086 Engine: Simulates CPU registers, status flags, and 5-stage bus cycle state transitions.
  4. Virtual Device Layer: Emulates 8 peripheral interfaces with direction enforcement and realistic state logic.
  5. Verification & Test Layer: Executes reproducible synthetic test suites and generates analytics.

J. Virtual Peripherals

Detailed hardware modeling is provided for each device:

  • Input Switch: Individual bit toggles modifying the byte value in real time.
  • LED Bar: Active-high illumination with glowing CSS effects reflecting accumulator bitmasks.
  • 7-Segment Display: Full 7-segment common-cathode decoding displaying hex characters 0–F.
  • Digital Sensor: Senses temperature from 0°C (00H) to 127°C (7FH) and higher.
  • Keypad: Encodes key press matrix coordinates into hex scancodes.
  • Buzzer: Synthesizes realistic 2.4kHz audio pulses using the HTML5 Web Audio API.
  • Motor Controller: Computes PWM duty cycle percentage and motor RPM (0–3000 RPM) with animated spinning fan.
  • Status Register: Decodes handshaking bit flags: READY, BUSY, ERROR, TX_EMPTY, RX_FULL, OVERRUN, PARITY_ERR, IRQ_PENDING.

K. Simulation Workflow

When an instruction executes:

  1. Fetch & Decode: Opcode is parsed; control signal M/~IO is set to 0.
  2. Address Latch (T1): Port address is placed on bus lines A7–A0; ALE is pulsed high.
  3. Bus Control Strobe (T2–T3): Active-low ~RD or ~WR strobe is asserted.
  4. Data Transfer (T3–T4): Peripheral drives or latches data across lines D7–D0.
  5. Register/Peripheral Update (T4): Accumulator AL or target peripheral updates its internal state.
  6. Trace Log Entry: Full snapshot is recorded into the audit trail table.

L. Normal Test Suite (TC01–TC10)

The verification suite validates reading and writing across all 8 peripheral ports, multi-instruction sequential pipelines, and data transfer from sensor to LED via the CPU accumulator with 100% precision.

M. Fault Detection Suite (FC01–FC06)

The system traps illegal operations gracefully:

  • FC01: Unmapped port address (e.g. IN AL, FFH) → Error: Port not mapped (High-Z).
  • FC02: OUT to input-only sensor → Error: Device does not accept output.
  • FC03: IN from output-only LED → Error: Device does not support read.
  • FC04: Invalid mnemonic syntax → Error: Unknown instruction.
  • FC05: Constant out of 8-bit range → Error: Value exceeds 00H–FFH limit.
  • FC06: Inverted operand order → Error: IN requires accumulator first.

N. Results Summary

The test runner reports 16 of 16 tests passing (100% pass rate). All bus control signals, register transitions, and peripheral updates match the physical behavioral specifications of the Intel 8086 microcomputer architecture.

O. Assumptions & Limitations

The simulation prioritizes educational clarity for Unit V I/O interfacing. It intentionally excludes physical propagation delays, analog slew rates, hardware interrupts (INTR/NMI), and direct memory access (DMA).

P. Future Enhancements

  • Support for 8255 Programmable Peripheral Interface (PPI) Mode 0, 1, and 2 simulation.
  • 8259 Programmable Interrupt Controller (PIC) vectoring.
  • Hardware-in-the-loop interfacing via Web Serial API to Arduino or FPGA boards.
  • Side-by-side comparison mode between Port-Mapped and Memory-Mapped I/O.
